# Police Dream Town — Police Discord Bot

بوت إدارة شرطة مبني باستخدام Python و`discord.py`. النسخة الحالية تستخدم لوحة مباشرة موحدة تجمع **الأزرار وقائمة المباشرين والعداد داخل رسالة واحدة**، ويتم تعديل الرسالة نفسها عند كل دخول أو خروج أو تغيير حالة.

## بنية المشروع الصحيحة

```text
police_bot/
├── main.py
├── config.py
├── database.py
├── utils.py
├── requirements.txt
├── .env.example
└── cogs/
    ├── __init__.py
    ├── login_panel.py
    ├── dispatch_center.py
    ├── setup_admin.py
    ├── clothing.py
    ├── gps_system.py
    ├── points_hours.py
    ├── tickets.py
    └── wings.py
```

يجب ألا يوجد مسار باسم `cogs/cogs`. يجب أن يكون ملف الدخول مباشرة في `cogs/login_panel.py`.

## لوحة المباشرة الموحدة

الأمر `/نشر_لوحة_الدخول` ينشر رسالة واحدة تحتوي على الأزرار وقائمة الأفراد والعداد:

```text
عدد المباشرين الآن ( 0 / 30 )
```

الحد الافتراضي 30 ويمكن تغييره من `MAX_ACTIVE_OFFICERS`. عند الضغط على زر، تُحدّث الرسالة نفسها ولا تُنشأ لوحة منفصلة.

تظهر الحالة التراكمية بجانب الاسم، مثل:

```text
اسم الضابط  ⚫️🟢🔴
اسم الضابط  ⚫️🟢🟢
اسم الضابط  ⚫️🟢🟢🔵
اسم الضابط  ⚫️🟢🟢⚪
```

الرموز تعني ضابطاً مباشراً، حالة دخول، بودي كام أوف/أون، دسباتش، ونائب دسباتش أو مسؤولية فترة. الضغط على الحالة يفعّلها أو يوقفها، بينما بودي كام أون وأوف حالتان متبادلتان.

## إعداد البيئة

انسخ `.env.example` باسم `.env` على Railway أو جهاز التشغيل، ولا ترفع `.env` إلى GitHub:

```env
BOT_TOKEN=توكن_البوت
GUILD_ID=معرف_السيرفر
ADMIN_ROLE_ID=معرف_رتبة_الإدارة
OFFICER_ROLE_ID=معرف_رتبة_الضباط
PERIOD_MANAGER_ROLE_IDS=معرف_رتبة_1,معرف_رتبة_2,معرف_رتبة_3
MAX_ACTIVE_OFFICERS=30
EMBED_IMAGE_URL=رابط_عام_اختياري_للصورة
```

يمكن لمسؤول الفترة امتلاك أكثر من رتبة. ضع معرفات هذه الرتب في `PERIOD_MANAGER_ROLE_IDS` مفصولة بفواصل. الإداري يستطيع استخدام اللوحة حتى لو لم يكن ضمن هذه الرتب.

## الهوية البصرية

تستخدم جميع اللوحات اللون الموحد وFooter باسم `Police Dream Town`. يمكن وضع رابط عام للصورة المرفقة في `EMBED_IMAGE_URL`، وستظهر كصورة صغيرة داخل Embed. Discord لا يدعم جعل الصورة خلفية كاملة للرسالة، لذلك لا يمكن استخدامها كخلفية خلف الأزرار نفسها.

## التشغيل على Railway

بعد رفع المشروع إلى GitHub، تأكد من أن `main.py` و`config.py` و`database.py` و`utils.py` في جذر المشروع، وأن ملفات `cogs` داخل مجلد واحد فقط. في Railway ثبّت المتطلبات ثم شغّل:

```bash
pip install -r requirements.txt
python main.py
```

بعد كل تحديث على GitHub يجب تنفيذ **Redeploy** في Railway. رفع الملفات إلى GitHub وحده لا يغيّر عملية البوت التي تعمل حالياً.

بعد التشغيل استخدم:

```text
/نشر_لوحة_الدخول
/فتح_تسجيل_الدخول
/قفل_تسجيل_الدخول
/حالة_المباشرة
/مدتي
```

## قاعدة البيانات

يحتفظ `police_bot.db` بسجلات المباشرة والساعات، ويضيف أعمدة الحالات الجديدة تلقائياً عند تشغيل النسخة الجديدة. لا تحذف قاعدة البيانات من الاستضافة إذا كنت تريد الاحتفاظ بالسجلات القديمة. يجب أن تكون صلاحيات البوت في القناة كافية لإرسال الرسائل وتعديلها وقراءة سجل الرسائل.

## قواعد المسؤوليات ووضع 0,1

لا يمكن للعضو تفعيل أكثر من مسؤولية واحدة من `دسباتش` أو `نائب دسباتش` أو `مسؤولية فترة` في الوقت نفسه. إذا حاول تفعيل مسؤولية ثانية، يرفض البوت العملية ويطلب إيقاف المسؤولية الحالية أولاً.

زر `0,1` يضع العضو في نهاية قائمة المباشرين، ويخفي دوائر حالاته مؤقتاً، ويوقف حساب الوقت. عند الضغط عليه مرة ثانية تعود الدوائر التي كانت محفوظة له ويستأنف حساب الوقت من لحظة العودة، ولا تُحسب مدة التوقف.
